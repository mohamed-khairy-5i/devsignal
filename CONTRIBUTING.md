# Contributing to DevSignal

Thank you for helping make DevSignal more useful for developers sharing their work.

## Before you start

Open an issue first when proposing a substantial feature or visual change. Explain the user problem, the expected outcome, and any interface examples that clarify the idea.

## Development workflow

1. Fork the repository and create a focused branch.
2. Install dependencies with `pnpm install`.
3. Run the development server with `pnpm dev`.
4. Keep the Atelier Terminal design language intact: ink surfaces, ivory artifacts, copper signals, practical developer-facing copy, and accessible contrast.
5. Run `pnpm run check` and `pnpm run build` before opening a pull request.

## Pull requests

Each pull request should solve one clear problem. Include a concise description, screenshots for visual changes, and reproduction steps for any bug fix. Do not include secrets, tokens, personal data, or generated build output.

## Good first contributions

- Improve keyboard navigation or accessibility labels.
- Add export-size presets for professional networks.
- Improve GitHub API error handling.
- Add translations or RTL support.
- Refine mobile card layouts.
